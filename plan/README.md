## 为什么需要规划

ReAct：像没开导航的司机

- 每个路口只看眼前，**走一步看一步**
- 搜了一堆结果，**用不好**
- 忘了做过什么，**重复搜索**
- 信息不全就**草率下结论**
- 工具失败后**原地重试**，直到 max_steps

共同点：只想“现在做什么”，没想“整体怎么做”

## 设计决策

三个刻意的简化

- 单一计划：一个问题一份清单，不管子计划
- 整体重写：每次更新都重新提交完整清单，不做“改第 3 项”这种局部修改
- 三种状态：pending / in_progress / completed

局部修改要维护索引和同步，最容易出 bug；5 - 10 项的清单，整体重写的成本可以忽略
